# 跨校落地手册 · 从普查到成品星图

> 面向：想把「校园猫咪星图」在自己学校复刻一遍的学生团队。
> 前提：一台能装 Python 的电脑（Windows / macOS / Linux 都行），一份猫咪名册，一堆实拍照片。
> 读完能做到的事：把普查原始记录变成一份**双击就能打开、不联网也能看**的定制星图 HTML + zip 包。
>
> 本手册里每一条「系统会怎么反应」都对应代码里的真实行为，括号里给了出处，便于自己核对。
> 全流程实测参照：中北大学 76 只猫、75 张实拍照片、原图 266.7MB（见 `docs/验收证据-场景2-全量76只.md`）。

---

## 0. 十分钟准备

### 0.1 装依赖

只需要四个包，全部远小于 100MB，没有需要编译的东西：

```bash
python -m venv .venv
# Windows
.venv\Scripts\pip install fastapi uvicorn python-multipart pillow
# macOS / Linux
.venv/bin/pip install fastapi uvicorn python-multipart pillow
```

### 0.2 启动控制台

```bash
# Windows
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8010
```

浏览器打开 <http://127.0.0.1:8010>。`--host 127.0.0.1` 是**故意**的：这套东西没有登录、没有权限体系，只该在本机跑。要给同伴看，让他们过来看屏幕，或者把生成好的 zip 发出去——**不要**把它挂到公网（挂上去等于任何人都能读写你的工作区）。

健康检查：`GET /healthz`。

### 0.3 数据放哪

所有产物都落在项目目录下的 `workspace/{项目id}/`，一个项目一个文件夹，删文件夹就是删项目（也可以用 `scripts/cleanup.py`，见 §12）。**源数据（原始照片、名册 Excel）请自己另存一份**——工作区里的照片是被压缩过的副本，不是原图。

如果你们学校已有一套总库目录（像 `E:\猫咪星图_总库` 那样按 `07_普查原始数据`、`08_原始照片视频` 分类），本工具**只读不写**：它不会去改总库里的任何文件，要归档就新建子目录。

## 1. 普查阶段：拍什么、记什么

星图的质量上限在普查就定死了。软件只能替你排版，不能替你认猫。

### 1.1 照片

- **每只猫至少一张能看清正脸/侧脸全身的照片**，这是「代表照片」，会直接进星图的详情卡。
- 其余照片算「关联照片」，只统计数量，不进产物（产物体积要能发得出去）。
- 拍摄时**顺手把环境拍进去**：猫在哪栋楼前、哪片草地，决定了后面「出没区域」能不能填得具体。
- 原图不用自己压。上传时系统统一压到长边 ≤1200px、单张 ≤200KB（`config.MAX_PHOTO_SIDE` / `MAX_PHOTO_BYTES`），76 只猫 75 张照片从 266.7MB 压到 14MB，星图上看不出差别。
- 文件名随意，系统只取 basename 并做安全化处理，压缩后统一输出 `.jpg`。所以名册里写 `照片视频/xxx.jpg` 也能对上（`validate.resolve_photo`）。

### 1.2 普查记录（batch 文本）

一线同学最容易坚持下来的记录方式是一行一条的纯文本。系统认这个格式（`app/census_parser.py`，8 个字段，`|` 分隔）：

```
文件名 | 猫数 | 毛色 | 特征 | 场景 | 画质 | 正脸 | 人脸
IMG_2043.jpg | 1 | 橘白（橘背橘头，胸腹发白） | 体型偏胖 粉鼻 左耳缺角 | 宿舍楼前石台 | A | 是 | 无
```

- **画质 A/B/C** 会被翻译成置信度 **高/中/低**。C（糊的、远的、只能看见一团毛）会自动标成「低」，而低置信度记录**按数据红线建议弃用**——宁可少一只猫，不要上一只认错的猫。
- **毛色**只取括号前的主色（`橘白（橘背橘头…）` → `橘白`），括号里的细节会进「特征描述」。
- **场景**会按关键词表映射成「出没区域」短语（宿舍/教学楼/食堂/车库/电动车停放区/草地植被区/石台区…）。只写「室内」「户外」这种修饰词是最后兜底，星图上会很难看——**尽量写到具体地点**。
- **正脸 / 人脸**两栏是给归并判断留的证据：有正脸的记录更容易确认是不是同一只猫；有人脸入镜的照片要注意肖像权，别当代表照片。

### 1.3 建档纪律

- 一只猫一个编号，编号格式 `CAT-001`（`cat_1`、`CAT 001` 也会被规整成 `CAT-001`，`csv_loader.normalize_id`）。
- **弃用的编号允许空缺**，系统只提示不拦截（`I_ID_GAP`）。别为了让编号连续而把认错的猫硬凑进去。
- 同一张照片被两只猫引用，八成是重复建档，系统会给警告（`W_PHOTO_SHARED`）。

## 2. batch → 名册草稿（F6）

控制台「F6 普查解析」卡片上传 `.txt`，或直接调接口：

```bash
curl -F "file=@普查-batch01.txt" -F "as_csv=true" \
     http://127.0.0.1:8010/api/census/parse -o 名册草稿.csv
```

`as_csv=true` 直接回一份可上传的 12 列 CSV 草稿；不加就是 JSON，便于自己再加工。解析结果会带**警告条数**和**归并建议组数**——警告不是失败，是「这几行你自己看一眼」。

草稿只是草稿：昵称、军衔、工位这些有创作成分的空着或填占位，后面在控制台里补（§5）。

## 3. 名册 CSV：12 列标准与别名

标准列（`config.ROSTER_COLUMNS`，顺序随意，缺列才报错）：

| 列名 | 必填 | 说明 | 可接受的别名 |
|---|---|---|---|
| 编号 | ✅ | `CAT-NNN` | `id` `ID` `cat_id` `序号` |
| 昵称 | ✅ | 猫的名字 | `名字` `name` `Name` |
| 军衔 | | 星图上的头衔，如「喵校长」「中士」 | `职级` `rank` |
| 工位 | | 职责描述，如「总揽全校猫务」 | `职务` `title` `岗位` |
| 毛色 | ✅ | 主色，用于分组配色 | `coat` `花色` |
| 特征描述 | | **越具体越好**，短于 4 字会提示 | `特征` `features` |
| 代表照片文件 | ✅ | 必须能在已上传照片里找到 | `代表照片` `photo` `照片文件` |
| 照片数量 | | 正整数，空或非法按 1 处理并警告 | `照片数` `photoCount` `photo_count` |
| 出没区域 | | 空则星位落入「未归类区」 | `区域` `area` `出没地点` |
| 关联照片编号 | | 追溯用，形如 `batch1:IMG_2043` | `关联照片` `related` |
| 置信度 | | 只认 `高/中/低` | `confidence` `可信度` |
| 备注 | | 随便写 | `note` `说明` |

**编码不用管**：utf-8-sig / utf-8 / gb18030 / gbk / big5 / latin-1 依次试（`csv_loader.decode_bytes`）。Excel 另存的「CSV UTF-8」和老式「CSV（逗号分隔）」都能读。

多出来的列会被忽略并提示（`I_UNKNOWN_COLUMN`），不会报错——所以从别的表里直接拷一版过来通常也能跑。

模板可以下载：`GET /api/template`。

## 4. 上传与校验（F1 / F2）

顺序是**先建项目 → 传名册 → 传照片 → 跑校验**。（先传名册再传照片也行，但校验必须在照片到位之后跑，否则会报一堆「代表照片未找到」。）

照片可以整包 zip 上传，系统会递归解包（最多 3 层嵌套）。四道限额，任何一道超了**整批回滚**，不会留下半个状态（`config.MAX_*`）：

| 限额 | 值 |
|---|---|
| 单个上传文件（含 zip） | 200MB |
| 单次请求入库张数 | 2000 |
| 项目累计张数 | 3000（≈600MB 磁盘） |
| 单个 zip 条目数 | 20000 |
| 单次请求累计解压字节 | 1GB（防 zip 炸弹） |

校验分三级，**只有 error 会拦住生成**：

- **error**：缺列、编号为空/非法/重复、必填字段为空、代表照片找不到、名册为空。
- **warning**：照片数量非法、置信度非法或为空、置信度为「低」、照片被两只猫共用。
- **info**：路径已归一、未识别列、特征描述过短、出没区域为空、编号空缺、照片上传了但没被引用。

校验报告可下载（`GET /api/projects/{pid}/report.md`），会一起打进 zip——**这是给后来人看的留痕**，别删。

## 5. 在线改名册（F10）

不用「下载 → Excel 改 → 再上传」这个循环了。控制台 F10 卡片直接行内编辑，接口是按「物理行号 + 标准列名」改单元格：

```bash
curl -X PATCH http://127.0.0.1:8010/api/projects/{pid}/roster \
     -H "Content-Type: application/json" \
     -d '{"edits":[{"line":7,"field":"昵称","value":"墩墩"}],"revalidate":true}'
```

- 行号从 **2** 开始（第 1 行是表头）。越界或列名不存在会被**单条拒绝**，其余照改，返回里 `applied` / `rejected` 分得清清楚楚。
- `revalidate: true` 会在回写后自动重跑校验，省一次点击。
- 回写用 utf-8-sig + 原子替换，中途断电不会得到半个 CSV。

### 5.1 加一只猫 / 删一只猫（不用再来回倒 CSV）

新猫入册、老猫不再出现，以前都得「下载 CSV → Excel 改 → 重新上传」。现在控制台 F10 卡片上有两个按钮，接口也在：

```bash
# 在第 7 行之后插一行（after 是物理行号，表头是第 1 行；插在表头之后就是 after=1）
curl -X POST http://127.0.0.1:8010/api/projects/{pid}/roster/rows \
     -H "Content-Type: application/json" \
     -d '{"after":7,"values":{"昵称":"新猫","毛色":"三花","代表照片文件":"d.jpg"}}'

# 删掉第 8 行
curl -X DELETE "http://127.0.0.1:8010/api/projects/{pid}/roster/rows/8"
```

两条都默认顺手重跑校验（`revalidate`／查询串 `?revalidate=false` 可关），回写走的是和改单元格**同一个落盘出口**，所以 `roster.csv` 与随包的 `data/猫咪名册.csv` 不会一半新一半旧。

两处**刻意不自动化**，跨校复制时别自作聪明给它「补上」：

- **插入不替你编编号。** `values` 里没有 `编号` 就是空着，校验会报 `E_BAD_ID`「编号为空」，由人决定用哪个号。工具自动补号（顺着最大值 +1）会让「弃用编号不复用」这条数据红线在没人看见的地方失效——被弃用的号一旦被重新发出去，历史照片和归并判定就全对不上了。
- **删行不删照片。** 那只猫的照片仍留在 `assets/photos/`，报告里以 `I_PHOTO_UNUSED`「已上传但名册未引用」浮出来。要不要清掉由人决定：可能是名册写错了照片名（该改行不该删行），也可能确实要删——但那是删文件，不该由一次「删行」顺手做掉。

控制台上的三个入口：

| 入口 | 什么时候用 |
|---|---|
| `＋ 加一只猫` | 展开一张表单，12 列都在，空着的列不发出去；插完表单不关，方便连着加下一只 |
| `－ 删一行` | 下拉列出**全部**数据行（`第 N 行 · 编号 昵称`），名册干净时也能删 |
| 问题行右侧 `✕ 删这行` | 校验摊开的错误/警告行里顺手删；名册干净时列表是空的，这时用上面那个 |

删完所有行号会往上挪，所以前端删一次就重读一遍名册，待改清单也会清空——留着旧行号继续改会改错行。

## 6. 归并工作台（F9）：疑似同一只猫怎么办

同一只橘白猫在宿舍区和食堂区各被建了一次档，是跨批次普查最常见的错误。

系统会自动找候选组，两类（`app/merge.py` `candidate_groups`，按可疑度降序）：

1. **共用同一张代表照片** —— 最可能是重复建档，无条件成组。
2. **同毛色 + 同出没区域**，且特征描述相似度（二字切片 Jaccard）≥ 0.12，组内 2~5 只。再大就不是「疑似重复」而是「同色猫扎堆」，没有比对价值。

找出来之后：

- 人工判定三选一：`same`（同一只猫）/ `different`（不是同一只）/ `unsure`（存疑待复核）。
- 判定「同一只猫」**必须写明保留哪个编号、弃用哪些编号**；判「同猫」或「不同猫」**必须写理由**（至少 2 字），「存疑」可以先空着。不满足会被 400 逐条拒绝，错误信息直接说人话（`merge.check_decision`）。
- 理由会进操作日志和 F7《归并决策摘要》——数据红线要求每条取舍都有人签字。
- **判定不会自动改名册。** 自动合并等于让程序替你做无法追溯的决定。判定完之后，回到 §5.1 用「－ 删一行」删掉重复行（或改 CSV 重传）自己动手：把照片数量合并、在备注里写「与 CAT-0XX 为同一只，已合并」。

摘要下载：`POST /api/projects/{pid}/summary`，随 zip 一起打包。

## 7. 底图与星位标定（F8）

不传底图也能出星图（星位按出没区域算法推导）。想让星星落在真实校园位置上：

1. 上传一张校园平面图/手绘地图（`POST /api/projects/{pid}/map`），长边会压到 ≤1920px。
2. 在 F8 卡片上**拖星星**到猫常出没的位置。坐标以归一化值存（0~1），越界直接 400 拒绝——所以换不同尺寸的底图，标过的星位不会跑偏。
3. 标定结果烘焙进产物的 `CALIB`，页脚会注明「星位人工标定 12/76」。没标定的那些仍是算法推导，页脚写「星位为算法推导（未人工标定）」——**产物不会假装全部人工标过**。
4. 后悔了：`DELETE /api/projects/{pid}/calib` 一键退回算法推导。

建议只标**地标级**的猫（长期固定出没、照片证据充分的那十几只），其余交给算法。全标一遍既慢又容易标错。

## 8. 主题：配色 / 字体 / 署名 / 校徽（F11）

- **5 套预设**：子夜金（默认）、极光青、晨曦橘、夜樱粉、墨青书院。全是深色底——星点是画在 canvas 上的亮色小圆点，换浅色底就是一片看不见星星的白。
- **8 个颜色可单独覆盖**：夜空底色、正文主色、次要文字、强调色、标题色、连线色、图例辅色、统计行文字。只收 `#RRGGBB`，其余一律丢弃并在面板上说明。改任一颜色即算「自定义」，**切换预设时会清空自定义**（自定义是相对旧预设的偏移，留着只会脏）。
- **5 种字体栈**：系统黑体、宋体、楷体、黑体、圆体。**不打包 webfont**——一个中文字体子集几 MB 起步、版权也说不清。代价是同一份产物在不同机器上长相有细微差别，这是取舍不是 bug。
- **页脚署名**（≤120 字）是**追加**，不是替换：数据源、生成日期、标定方式这三样是留痕要求，想加自己的落款可以，想把出处抹掉不行。署名会 HTML 转义，写 `<script>` 也只会显示成文字。
- **校徽**：png / jpg / webp / bmp / gif，**不收 svg**（svg 能带脚本，而产物是要挂到学校公众号上的）。自动缩到长边 ≤256px 并转成 PNG，**保留透明区**——校徽糊个白底会在深色星图上留一个白方块。原图上限 4MB。

> ⚠️ 主题改动只影响**之后**生成的产物。改完要重新点「生成星图」。

## 9. 生成与打包（F3 / F4 / F5）

两种形态，按用途选：

| | `relative`（HTML + assets） | `inline`（单文件） |
|---|---|---|
| 长相 | 一个文件夹，HTML + `assets/` | 一个 `.html` 文件 |
| 照片 | 独立 jpg 文件 | base64 内嵌，分片成 `assets/photo-data-NN.js` |
| 校徽 | `assets/logo.png` | base64 进 HTML |
| 适合 | 挂网站、放共享盘、要二次编辑 | 发微信群、发邮件、拷 U 盘 |
| 体积（76 只实测） | zip 14230KB | zip 14339KB |

两种都**不引用任何外部资源**：没有 CDN、没有外链字体、没有在线图片。断网双击就能开。inline 版打开会慢一两秒（要解 base64），76 只猫的量级完全能接受。

zip 里固定有：星图 HTML、`data/猫咪名册.csv`、`校验报告.md`、`归并决策摘要.md`，relative 版另加 `assets/map.jpg`、`assets/photos/*`、`assets/logo.png`。**报告和摘要一定要跟着发出去**——那是这份星图能被别人复核的唯一依据。

在线预览：控制台 iframe 直接看（`GET /api/projects/{pid}/preview?form=inline`）。
下载：`GET /api/projects/{pid}/download?form=relative`，文件名是 `{校名}-校园猫咪星图-{YYYY-MM-DD}.zip`。

## 10. 发布前的自查清单

- [ ] 校验报告里 **error = 0**，warning 逐条看过并有处置（改掉了，或在备注里写明为什么留着）。
- [ ] 置信度「低」的记录已弃用，或已在备注里说明保留理由。
- [ ] 归并候选组**全部**有判定和理由，没有 `unsure` 挂着不管的。
- [ ] 产物页脚的三样留痕齐全：数据源、生成日期、标定方式。
- [ ] 打开产物，随便点三颗星：照片能出、昵称/毛色/特征对得上、出没区域不是「未归类」。
- [ ] **断网**再打开一次（inline 版尤其要试）。
- [ ] 有人的照片没被当成代表照片（肖像权）。
- [ ] zip 发给一个不在项目组的同学，让 TA 双击试试——TA 打不开就是没做完。

## 11. 常见脏 CSV 清单

按「症状 → 系统怎么报 → 怎么改」排。**加粗的是 error，会拦住生成**。

| 症状 | 系统反应 | 怎么改 |
|---|---|---|
| **表头是「序号」而不是「编号」** | 认得，别名表里有 | 不用改 |
| **表头写了「猫咪名字」这种自创列名** | `I_UNKNOWN_COLUMN` 忽略该列 + `E_MISSING_COLUMN` 缺「昵称」 | 把表头改成别名表里的任意一个，或补一列标准名 |
| **Excel 另存成了 .xlsx** | 上传接口只吃 CSV，解析不出表头 | 另存为「CSV UTF-8（逗号分隔）」 |
| **用分号/制表符分隔** | 整行被当成一列 → 缺列报错 | 另存时选逗号分隔 |
| **编号写成 `1`、`A01`、`CAT-001A`** | **`E_BAD_ID`：不符合 CAT-NNN 格式** | 改成 `CAT-001`（`cat_1`、`CAT 001` 都行，会自动规整） |
| **编号重复（跨批次各建了一次）** | **`E_DUP_ID`：编号 CAT-012 重复出现（第 2 次）** | 走 §6 归并工作台判定，然后删掉重复行 |
| **编号跳号（CAT-071 缺失）** | `I_ID_GAP` 提示，不拦 | 不用改。弃用编号本该空着 |
| **昵称/毛色/代表照片为空** | **`E_REQUIRED_FIELD`** | 补齐。实在没有照片的猫，先别建档 |
| **照片列写的是绝对路径 `D:\照片\xxx.jpg`** | `I_PHOTO_PATH_NORMALIZED`，按 basename 归一 | 不用改，但建议只写文件名 |
| **照片列写 `xxx.png`，实际压缩后是 `xxx.jpg`** | 按 stem 兜底匹配成功，给一条归一提示 | 不用改 |
| **照片列的文件根本没上传** | **`E_PHOTO_MISSING`** | 补传照片，或改指向真实存在的文件 |
| **两张猫用了同一张照片** | `W_PHOTO_SHARED`：可能是重复建档 | 查是不是同一只猫（§6）；确实共用就换一张 |
| **照片数量写成「3张」「若干」「-」** | `W_BAD_COUNT`，按 1 处理 | 改成纯数字 |
| **置信度写成「高置信」「A」「★」** | `W_BAD_CONFIDENCE` | 只认 `高` / `中` / `低` |
| **置信度是「低」** | `W_LOW_CONFIDENCE`：按数据红线建议弃用 | 弃用，或补拍照片重新判定 |
| **特征描述只写「橘猫」** | `I_THIN_FEATURE`（短于 4 字） | 写清体型、斑纹位置、五官、伤疤——这是别人实地对照的唯一依据 |
| **出没区域为空** | `I_NO_AREA`：星位将落入未归类区 | 补具体地点；星图上「未归类」挤成一团很难看 |
| **上传了 200 张照片，名册只引用 76 张** | `I_PHOTO_UNUSED` 逐张提示 | 正常。关联照片不进产物，只是留档 |
| **整个 CSV 只有表头** | **`E_EMPTY_ROSTER`** | 检查是不是另存时只存了选中区域 |
| **CSV 是从 Word 里拷出来的，带全角逗号** | 列数对不上 → 缺列报错 | 用 Excel/文本编辑器重新另存 |
| **文件是 GBK 编码，中文全乱码** | 自动探测 gb18030/gbk，不会乱 | 不用改 |

### 上传相关的硬失败

| 症状 | 原因 | 怎么办 |
|---|---|---|
| HTTP 413 | 单个文件/zip 超过 200MB，或累计解压超过 1GB | 分批传；zip 里别塞视频 |
| HTTP 400「不是有效图片」 | 文件扩展名是图片但内容不是 | 重新导出 |
| 收下的张数比选的少 | 同名文件去重，或扩展名不在 `.jpg .jpeg .png .webp .bmp .gif` 里 | 看返回里的 `skipped` 字段 |
| 请求卡住、后来报锁超时 | 同一个项目上有另一个写操作在跑（锁超时 180 秒） | 等进度条走完；别在生成途中再点上传 |

## 12. 日常运维

- **看进度**：上传压缩和生成打包都是长任务，控制台有进度条，接口是 `GET /api/projects/{pid}/progress`。
- **清工作区**：`python scripts/cleanup.py --before 7d`（干跑，只列出）→ 确认无误再加 `--apply`。也可以 `--keep-latest 3` 保住最近三个项目。脚本只认项目内的 `workspace/`，路径不对直接拒绝执行。
- **保护名单**：`--exclude` 按子串匹配项目 id 或学校名，可重复给、也可用逗号分隔。被报告/交付物引用过的项目要写进名单，否则下次清理会把证据一起删掉：

  ```bash
  python scripts/cleanup.py --before 1h \
    --exclude 1788707789-示例校 --exclude _ui_demo --apply
  ```

  名单里有项**没匹配到任何项目**时，`--apply` 会直接拒绝执行（退出码 2）——写错了名字还照删，等于把「我以为保住了」变成一句空话；干跑则只在 stderr 上提醒一句。`--json` 输出里带 `exclude_patterns` / `excluded` / `unused_excludes` 三个字段，可以机器核对。
- **项目列表**：控制台支持分页与搜索（`GET /api/projects?limit=50&offset=0&q=中北`）。
- **换机器**：整个项目目录拷走即可，没有数据库、没有注册表、没有隐藏配置。工作区就是文件系统本身。

## 13. 一条命令跑完全程（可复制）

```bash
BASE=http://127.0.0.1:8010

# 1. 建项目
PID=$(curl -s -X POST $BASE/api/projects \
  -H "Content-Type: application/json" \
  -d '{"school":"示例大学","subtitle":"校园猫咪普查 2026 秋"}' | python -c "import sys,json;print(json.load(sys.stdin)['id'])")

# 2. 上传名册与照片（照片也可以传 zip）
curl -s -X POST $BASE/api/projects/$PID/roster -F "file=@名册.csv"
curl -s -X POST $BASE/api/projects/$PID/photos -F "files=@a.jpg" -F "files=@b.jpg"

# 3. 校验，看报告
curl -s -X POST $BASE/api/projects/$PID/validate | python -m json.tool | head -30
curl -s $BASE/api/projects/$PID/report.md -o 校验报告.md

# 4.（可选）底图、标定、主题、校徽
curl -s -X POST $BASE/api/projects/$PID/map   -F "file=@校园地图.jpg"
curl -s -X PUT  $BASE/api/projects/$PID/theme -H "Content-Type: application/json" \
     -d '{"preset":"dawn","footer_signature":"示例大学学生会 · 校园猫咪普查小组"}'
curl -s -X POST $BASE/api/projects/$PID/logo  -F "file=@校徽.png"

# 5. 生成 + 打包 + 归并摘要
curl -s -X POST $BASE/api/projects/$PID/generate -H "Content-Type: application/json" -d '{"form":"inline"}'
curl -s -X POST $BASE/api/projects/$PID/summary > /dev/null
curl -s "$BASE/api/projects/$PID/download?form=inline" -o 星图.zip
```

出错时先看返回的 JSON：这套接口**几乎不返回空的 500**，非法输入都会在 `rejected` / `skipped` / `issues` 里逐条说明原因。
